# 2차 개발 벤치마크 — 2026-10-25

기준 커밋: `9a1fd0ccb3f1592fd498dcf9a08e7bbe25fd7ad8` / 점검기 9.6.1. 변경 후: 점검기 9.7.0.

기존 테스트와 별도로 자체 작성한 66개 사례를 코드 수정 전에 고정했다. 60개는 기계 점검, 6개는 의미 대조용이다. 외부 번역 전문이나 사람 평가 데이터를 사용하지 않았다. 분할 이름 development·verification은 자체 사례 구분이며 독립 심사자나 외부 검증을 뜻하지 않는다. 양쪽 결과 파일은 같은 fixture SHA-256을 기록한다. CRLF는 LF로 정규화해 운영체제 간 같은 파일을 비교한다.

| 기계 점검 범주 | 수정 전 | 수정 후 |
|---|---:|---:|
| HTML·XML 구조와 변수 연결 | 10/20 | 20/20 |
| ICU 변수·제어문 반복 | 8/16 | 16/16 |
| 숫자·날짜·코드 보존 | 12/12 | 12/12 |
| 분야별 용어집 | 6/6 | 6/6 |
| 작업 재개·변경 감지 | 6/6 | 6/6 |
| 합계 | 42/60 | 60/60 |

개발 분할은 23/32→32/32, 검증 분할은 19/28→28/28이다. 이번 기계 점검 사례 안에서 놓친 손상은 18→0, 정상 번역의 오차단은 0→0, 강제 종료는 0→0이었다. 이 수치는 한국어 번역 정확도·독자 선호·전체 입력의 무결함 비율이 아니다.

### 실제 보완

1. 전체 변수 개수가 같아도 `{price}`가 가격 요소에서 재고 요소로 옮겨지는 손상을 확인한다. HTML·XML의 태그와 보호 속성 경로에 변수를 연결한다. 변수 순서를 같은 요소 안에서 바꾸거나 요소 전체를 순서만 바꾸는 정상 변환은 허용한다.
2. ICU 변수·제어문을 집합으로만 보던 검사를 반복 횟수 대조로 보강했다. 언어별 plural 분기는 동시에 실행되지 않으므로 분기별 최대 횟수로 대조하며 정상적인 한국어 복수형 축약은 허용한다. select·명시 값 분기는 따로 유지한다.

식별 속성도 계층 차이도 없는 동일 형제 요소끼리의 의미 교환, plural 분기별 의미 해석, 문자열 본문의 주장·인과 오류까지 검증하는 것은 아니다. 이 한계는 원문 대조로 확인해야 한다.

### 의미 검토 6개는 별도 보고

가능성 확정, 행위 주체 교환, 일부→전체, 부정 반전, 시간 순서→인과, 주장 귀속 삭제 사례다. 현재 모두 자동 검사에서는 pass가 나왔다. 이를 성공으로 세지 않았으며 기계 점검 60개의 분모에서도 제외했다. 이 수치는 자동 검사 통과만으로 원고를 채택할 수 없다는 개발용 증거다. 사람의 독립 평가를 수행했다고 주장하지 않는다.

### 재현

```sh
python scripts/benchmark_round2.py --check
python scripts/benchmark_round2.py --output benchmarks/round2-rerun.json --check
```

`--check`는 기계 점검 불일치가 있으면 종료 코드 1을 반환한다. 프로그램 예외를 손상 차단 성공으로 세지 않는다. 의미 검토 사례는 출력에 남기되 자동 번역 품질 점수로 바꾸지 않는다. 원본 결과는 [수정 전](round2-baseline.json), [수정 후](round2-after.json)에 있다.
