# 의미 오류 재시도 — 2026-10-25

현재 대화 세션의 언어모델이 원문과 번역문을 실제로 읽고 명제·관계를 대조했다. Python 규칙을 늘려 6문장을 억지로 맞힌 결과가 아니다. 이번에 작성한 판정·근거를 [모델 검토 기록](semantic-retry-model-reviews.json)에 보존하고 점검기에 연결했다.

| 사례 | 기록된 모델 검토 결과 |
|---|---:|
| 원래 놓친 의미 오류 | 6개 모두 후보 지적 |
| 새로 작성한 의미 오류 | 6개 모두 후보 지적 |
| 정상 번역·반례 | 18개에서 후보 지적 없음 |

원래 6개의 기계 검사 결과는 여전히 pass다. 모델 보고서를 연결했을 때 SEM-1~6 후보와 warn으로 구분된다. 따라서 오프라인 Python 코드가 스스로 의미를 이해하게 됐다거나 새 입력에서도 같은 성적을 낸다는 뜻이 아니다.

정상·반례에는 `May I…` 허가 요청, 수동태→능동태, 한국어 주어 생략, `not all` 부분 부정, `not only` 포함 구문, 실제 because 인과, 발언 주체 위치 이동을 포함했다. 문제 후보마다 원문·번역문 구절과 판단 이유를 남겼다. 오류·정상 라벨을 보고서에서 자동 복사하는 코드는 사용하지 않았다.

**평가 한계:** 같은 세션이 사례·라벨을 작성하고 검토했다. 정답 라벨을 가리지 않았으며 독립 심사·블라인드 평가가 아니다. 수치는 저장한 판정과 자체 라벨의 일치 기록이며 검증된 의미 검출 정확도나 독립적인 오탐률이 아니다. 다른 원고에는 새 모델/사람 검토가 필요하다.

## 재현 범위

```sh
python scripts/benchmark_semantic_retry.py --check
```

스크립트는 [사례](../tests/fixtures/semantic_retry.json), 저장한 판정, 현재 점검기의 보고서 검증을 재현한다. 새 모델 추론을 실행하지 않는다. 전체 결과와 두 입력 파일의 지문은 [결과 JSON](semantic-retry-results.json)에 있다.

실제 새 원고 검토는 [의미 검토 연결](../references/translation-semantic-review.md)을 따른다. 보고서가 없으면 not_checked, 일부만 읽었으면 partial, 파일이 바뀌면 stale로 구분한다. 검토 범위·해시·근거 검증을 통과했다는 사실도 판단의 정확성 인증은 아니다.
