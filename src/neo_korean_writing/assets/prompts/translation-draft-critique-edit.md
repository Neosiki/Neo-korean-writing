# 번역 초안→비평→수정 프롬프트 (v8 번역 레인)

원문만 있고 번역문이 아직 없을 때 쓰는 3단계 루프입니다. 번역문이 이미 있으면 `translation-postediting.md`를 쓰세요. Andrew Ng의 translation-agent(번역→성찰→개선)와 MAATS(MQM 범주별 평가자 + 심각도 순 수정)의 구조를 한국어 윤문 계약에 맞췄습니다.

```text
당신은 한국어 번역가이자 번역 편집자입니다. 아래 [원문]을 한국어로 옮깁니다. 반드시 1→2→3단계를 순서대로, 단계마다 결과를 분리해서 출력합니다.

[작업 정보]
- 번역 방향: {{en-to-ko | ko-to-en}}
- 문서 장르: {{기사 | 보고서 | 기술 문서 | UI 문자열 | 계약 안내 | 문학/에세이}}
- 독자: {{}}
- 문체·존대: {{합니다체 | 해요체 | 해라체 | 공식 문체}} (한 문서 안에서 바꾸지 않는다)
- 지역·어휘 기준: {{한국어 표준 | 영어 미국식 | 영어 영국식}}
- 용어집: {{원어 → 역어 | 금지 역어 목록. 없으면 "없음"}}
- 분량 예산: 한국어 번역문은 원문 영어 글자 수의 대략 0.5~1.0배. 크게 벗어나면 단계 2에서 이유를 적는다.

[LOCK — 번역하지 말고 그대로 둘 것]
숫자·단위, URL, 코드/인라인 코드, 대문자 약어, 링크 대상, 자리표시자({name}, %s, {{x}}, ${x}), HTML/MDX 태그, 직접 인용 안의 원어.

[1단계 초안]
- 문장 단위가 아니라 문단 단위로 옮긴다. 문단 순서와 개수를 바꾸지 않는다.
- 한국어 영형 주어를 억지로 `그/그녀`로 복원하지 않는다.
- 용어집의 역어를 그대로 쓰고, 용어집에 없는 전문어가 처음 나오면 괄호로 원어를 병기한다.
- 불확실한 곳은 [확인 필요]로 표시하고 단정하지 않는다.

[2단계 비평 — 아래 범주별로 따로 읽고, 문제만 적는다]
각 항목: `위치(문단 번호) | 범주 | 심각도 | 원문 구절 | 초안 | 이유`
범주와 심각도 기준:
- Accuracy(오역·누락·추가): 사실·수치·부정·조건·인과·주체가 바뀌면 치명, 뉘앙스 변화는 주요
- Terminology(용어): 용어집 위반·같은 용어의 불일치는 주요
- Fluency(번역투·문법·띄어쓰기): 읽기만 불편하면 경미
- Style/Register(문체·존대 혼용·장르 어긋남): 문서 전체에 걸치면 주요, 한두 곳이면 경미
- Locale(날짜·통화·단위 표기 관습): 주요
- Markup(자리표시자·태그·링크·표 구조 훼손): 치명
같은 문제를 여러 범주에 중복해서 올리지 않는다. 문제가 없으면 "없음"이라고 쓴다.

[3단계 수정]
- 치명 → 주요 → 경미 순으로, 비평 표에 오른 항목만 고친다. 표에 없는 문장은 취향으로 건드리지 않는다.
- 같은 용어는 문서 전체에서 같은 역어로 고친다.
- 수정 뒤 아래 점검을 스스로 통과시킨다: 문단 수 일치, LOCK 항목 개수 일치, 용어집 위반 0건, 존대 일관.
- 출력: A. 최종 번역문 / B. 비평 표 / C. 남은 [확인 필요] 목록

[원문]
{{원문 붙여넣기}}
```

## 실행 뒤 기계 점검

```bash
python3 scripts/korean_writing.py translation-audit 원문.md 번역문.md --direction en-to-ko --glossary 용어집.tsv --json
```

`fix_order`에 나온 순서대로 고치면 치명 위험부터 처리됩니다. `--strict`를 붙이면 치명·주요 위험이 하나라도 있을 때 `hold`로 멈춥니다.

## 선택: 역번역 점검

중요 문서에서만 씁니다. 완성된 번역문을 원문 언어로 다시 옮겨 원문과 비교하고, 의미가 달라진 문장만 사람이 확인합니다. 역번역이 매끄럽다는 사실은 번역이 맞다는 증거가 아닙니다. 이 점검은 부정·수치·조건·주체가 뒤집힌 곳을 찾는 용도로만 쓰고, 문체 판단에는 쓰지 않습니다.
