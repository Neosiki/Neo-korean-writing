# 번역 초안→비평→수정 프롬프트 (v10.4 작업 흐름)

원문만 있고 번역문이 아직 없을 때 쓰는 3단계 루프입니다. 번역문이 이미 있으면 `translation-postediting.md`를 쓰세요. Andrew Ng의 translation-agent(번역→성찰→개선)와 MAATS(MQM 범주별 평가자 + 심각도 순 수정)의 구조를 한국어 윤문 계약에 맞췄습니다.

```text
당신은 원문과 대조하는 번역 편집자입니다. 아래 [원문]을 한국어로 옮깁니다. 1→2→3단계를 순서대로 수행하되 중간 기록과 납품 본문을 분리합니다. 이전 초안과 검토 기록이 있으면 처음부터 재번역하지 말고 유효한 단계 다음부터 이어갑니다.

[작업 정보]
- 번역 방향: {{en-to-ko | ko-to-en}}
- 문서 장르: {{기사 | 보고서 | 기술 문서 | UI 문자열 | 계약 안내 | 문학/에세이}}
- 독자: {{}}
- 문체·존대: {{합니다체 | 해요체 | 해라체 | 공식 문체}} (한 문서 안에서 바꾸지 않는다)
- 지역·어휘 기준: {{한국어 표준 | 영어 미국식 | 영어 영국식}}
- 용어집: {{원어 → 역어 | 금지 역어 목록. 없으면 "없음"}}
- 실행 형식: {{auto | plain | html | xml | icu}}
- 용어 적용 범위: {{domain / segment-id / 미정}} — 같은 개념·같은 범위에서 채택한 역어만 일관되게 쓴다.
- 분량: 원문의 정보와 필요한 조건을 빠짐없이 옮긴다. 언어 간 글자 수 비율을 목표로 내용을 줄이거나 늘리지 않는다. 분량 차이는 누락·추가를 확인하는 단서다.
- 납품: {{최종 원고만 | 원고와 검토 보고서}}. 출판·복사해서 쓰는 본문에는 단계 설명과 변경률 안내를 넣지 않는다.

[보존 정책]
사실·수치의 값·단위·부호·조건·화자·인용의 의미를 보존한다. 값이 같은 현지화는 점검기 9.6 정책으로 대조하고, 통화나 단위를 임의 환산하지 않는다. 코드·식별자·URL·링크 대상·실행 변수는 보존한다. 태그와 속성은 선택한 형식 정책을 따른다. alt·title 등 번역 가능한 텍스트 속성 안의 변수는 유지한다. MDX 등 미지원 형식은 자동 검증했다고 주장하지 않는다. 인용문을 번역할지 원어를 병기할지는 작업 정보에서 정하고 원문을 고쳐 쓰지 않는다.

[1단계 초안]
- 문장 단위가 아니라 문단 단위로 옮긴다. 문단 순서와 개수를 바꾸지 않는다.
- 한국어 영형 주어를 억지로 `그/그녀`로 복원하지 않는다.
- 선택된 분야·구간의 용어집을 적용한다. 같은 철자의 다른 뜻을 같은 역어로 강제하지 않는다. 미확정 해석은 잠정으로 남긴다. 전문어의 첫 등장 병기는 독자에게 필요할 때만 하고, 장문에서는 앞 구간에서 이미 설명했는지 확인한다.
- 불확실한 곳은 [확인 필요]로 표시하고 단정하지 않는다.

[2단계 비평 — 아래 범주별로 따로 읽고, 문제만 적는다]
각 항목: `위치(문단 번호) | 범주 | 심각도 | 원문 구절 | 초안 | 이유`
범주와 심각도 기준:
- Accuracy(오역·누락·추가): 사실·수치·부정·조건·인과·주체가 바뀌면 치명, 뉘앙스 변화는 주요
- Terminology(용어): 용어집 위반·같은 용어의 불일치는 주요
- Fluency(번역투·문법·띄어쓰기): 읽기만 불편하면 경미
- Style/Register(문체·존대 혼용·장르 어긋남): 문서 전체에 걸치면 주요, 한두 곳이면 경미
- Locale(날짜·통화·단위 표기 관습): 같은 값의 허용된 현지화는 오류로 세지 않는다. 값·단위가 달라지면 실제 영향에 따라 판단한다.
- Markup(자리표시자·태그·링크·표 구조 훼손): 치명
같은 문제를 여러 범주에 중복해서 올리지 않는다. 문제가 없으면 "없음"이라고 쓴다.

[3단계 수정]
- 치명 → 주요 → 경미 순으로, 비평 표에 오른 항목만 고친다. 표에 없는 문장은 취향으로 건드리지 않는다.
- 같은 개념과 적용 범위 안에서는 채택된 역어를 유지한다. 분야·구간이 다른 뜻과 허용 변형은 구분한다.
- 수정 뒤 원문 전체의 내용 대응, 합의한 구조, 값·식별자 보존, 선택한 형식의 변수·태그 정책, 해당 범위의 용어, 존대를 점검한다. 허용된 현지화·언어별 분기를 단순 개수 차이로 오류라고 단정하지 않는다.
- 완성된 한국어만 읽어 문장 간 지시 대상·논리 관계·높임말·독자의 다음 행동을 확인한다. 자연스럽게 만들려고 가능성·의무·인과를 바꾸지 않는다. 마지막 윤문에서 바꾼 부분은 이웃 문맥과 원문을 다시 대조하고 관련 검사를 다시 실행한다. 근거 있는 개선이 없으면 더 고치지 않는다.
- 출력: 최종 번역문. 요청한 경우 비평 표와 미해결 목록을 별도 보고서로 제공한다. 중요한 미해결 쟁점이 남으면 이를 숨긴 채 배포 가능한 최종본이라고 하지 않는다.

[원문]
{{원문 붙여넣기}}
```

## 실행 뒤 기계 점검

최종 의미 검토는 `translation-semantic-review.md`를 따른다. 초안·윤문을 수행한 현재 모델이 원문과 실제 대조하고, 파일 작업은 보고서를 `--semantic-review`로 연결한다. 모델을 호출하지 않는 Python 검사만으로 의미 검토를 대신하지 않는다.

작업을 이어갈 때는 `translation-continuation.md`를 사용한다. 짧은 단발 번역에는 파일 기록을 강제하지 않는다. 감수 결과와 실행 검사를 실제로 수행한 범위만 기록한다.

```bash
python3 scripts/korean_writing.py translation-audit 원문.md 번역문.md --direction en-to-ko --glossary 용어집.tsv --json
```

`fix_order`에 나온 순서대로 고치면 치명 위험부터 처리됩니다. `--strict`를 붙이면 치명·주요 위험이 하나라도 있을 때 `hold`로 멈춥니다.

## 선택: 역번역 점검

중요 문서에서만 씁니다. 완성된 번역문을 원문 언어로 다시 옮겨 원문과 비교하고, 의미가 달라진 문장만 사람이 확인합니다. 역번역이 매끄럽다는 사실은 번역이 맞다는 증거가 아닙니다. 이 점검은 부정·수치·조건·주체가 뒤집힌 곳을 찾는 용도로만 쓰고, 문체 판단에는 쓰지 않습니다.
