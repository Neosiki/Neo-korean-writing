# 원소스 변환

한 편의 글을 다른 채널용으로 바꾸는 절차다. 변환은 새 글 쓰기가 아니라 편집이다. 원본에 없는 사실·사례·경험을 보태지 않으며 변환본의 수치·명칭·인용은 원본과 대조한다.

## 순서

1. 원본의 한 문장 주장을 뽑는다. 뽑히지 않으면 변환 전에 Editorial Audit으로 원본부터 본다.
2. 대상 채널에 가져갈 내용을 고른다. 줄이는 변환이면 무엇을 뺐는지 기록한다.
3. [채널 플레이북](channel-playbooks.md)에 맞춰 다시 짠다. 도입은 채널에 맞게 새로 고르되 재료는 원본에서 가져온다.
4. `preserve`로 가져간 수치·인용이 원본과 같은지 확인한다. 변환은 분량이 크게 달라지므로 변경률 게이트 대신 보호 구간과 누락 기록으로 판단한다.
5. `channel-check`로 형식을 검사한다.

## 변환 표

| 원본 → 대상 | 가져갈 것 | 바꾸는 것 | 조심할 것 |
|---|---|---|---|
| 칼럼 → 스레드 | 핵심 판단 1개, 가장 강한 근거 1~2개 | 세 포스트로 압축, 포스트마다 독립적으로 | 조건·단서가 빠져 단정으로 바뀌는 것 |
| 칼럼 → 페이스북 평문 | 판단, 근거, 필자의 작업 장면 | 소제목 제거, 줄바꿈으로 구조화, 첫 화면 다시 쓰기 | 굵게·목록 기호가 남는 것 |
| 칼럼 → 네이버 블로그 | 독자 질문에 답하는 부분 | 검색 의도 하나로 좁힘, 소제목·사진 자리 추가 | 본문에 없는 체험을 후기처럼 쓰는 것 |
| 보고서 → 칼럼 | 결론과 그 근거 | 항목 나열을 논증 순서로 | 내부용 수치·명칭의 공개 가능 여부 |
| 강의 원고 → 칼럼 | 핵심 메시지 1~2개와 사례 | 구어를 문어로, 시간 순서를 논증 순서로 | 청중 반응·현장 농담을 사실처럼 옮기는 것 |
| 컨설팅 보고서 → 사례 글 | 문제, 조치, 결과 | 대상을 가명·익명으로, 독자 중심 순서로 | 매장·대표 식별 정보, 동의받지 않은 수치 |
| 긴 글 → 뉴스레터 | 이번 호 주제 한두 가지 | 요약 + 원문 링크 | 링크·날짜·신청 방법 오기 |
| 책 원고 한 장 → 칼럼 | 논지 1~2개 | 앞 장을 읽지 않아도 통하게 전제 보충 | 전제 보충에 원고 밖 사실을 쓰는 것 |

공개 가능 여부와 가명 처리는 사용자가 정한다. 확인되지 않았으면 `[확인 필요]`로 두고 발행본으로 내지 않는다.

## 줄이는 변환의 기록

분량이 절반 이하로 줄면 납품 본문과 따로 다음을 남긴다.

- 가져간 주장과 근거
- 뺀 내용 중 독자의 판단을 바꿀 수 있는 것(조건, 반례, 한계)
- 단정의 세기가 달라진 문장이 있는지

조건이 빠져 단정이 세지면 요약이 아니라 의미 변경이다. 자리가 모자라도 조건을 한 구절로 남긴다.

## 여러 채널을 한 번에

같은 원본으로 여러 채널본을 만들 때는 원본을 기준본으로 고정하고 채널본마다 원본과 대조한다. 채널본끼리 서로 베끼면 오류가 옮겨 간다. 수치가 여러 문서에 걸치면 `context-audit`로 불일치를 찾는다.
