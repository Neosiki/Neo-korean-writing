# 사업계획서 발표 원고와 슬라이드 문안

제출한 사업계획서를 발표 평가·데모데이·투자 설명용으로 옮기는 절차다. 이 스킬은 슬라이드에 들어갈 문안과 발표 원고를 만든다. 슬라이드 파일(.pptx 등)의 디자인과 생성은 환경에 있는 발표 자료 도구에 맡긴다.

발표 자료는 본문의 변환이다. 본문에 없는 수치·실적·계획을 발표에서 새로 만들지 않는다. 본문 제출 뒤 달라진 사실(새 계약, 테스트 결과)은 사용자가 준 것만 넣고 "제출 이후"라고 밝힌다.

## Step 1. 발표 조건 확인

- 발표 시간과 질의응답 시간. 공고나 안내문의 값을 따른다
- 듣는 사람: 정부지원사업 평가위원 / 투자자 / 일반 청중
- 자료 형식 제한: 장수, 파일 형식, 화면 비율, 영상 허용 여부
- 평가 항목. 발표 평가의 항목이 서면과 다르면 그 항목에 맞춰 순서를 잡는다

## Step 2. 이야기 순서 고르기

| 순서 | 흐름 | 맞는 경우 |
|---|---|---|
| 문제 먼저 | 문제 → 해결 → 시장 → 사업 방식 → 팀 → 요청 | 고객의 문제가 낯설거나 공감이 필요할 때. 기본값 |
| 성과 먼저 | 지금까지의 성과 → 그것이 가능했던 이유 → 시장 → 다음 계획 → 요청 | 매출·이용자·계약 같은 실적이 있을 때 |
| 시장 먼저 | 시장의 변화 → 생긴 기회 → 해결 → 진입 계획 → 팀 → 요청 | 제도·기술 변화가 사업의 출발점일 때, 기업 고객 대상일 때 |

성과 먼저는 실적이 신청자 카드에 증빙과 함께 있을 때만 고른다.

## Step 3. 장 구성

한 장에 메시지 하나. 발표 시간 1분에 한두 장을 출발점으로 삼고 리허설로 조정한다.

| 장 | 메시지 | 본문에서 가져올 곳 |
|---|---|---|
| 표지 | 사업을 한 문장으로 | 개요 |
| 문제 | 누가 무엇을 겪는가 | 문제인식 |
| 문제의 크기 | 숫자 하나와 출처 | 문제인식의 통계 |
| 해결 | 무엇을 만드는가 | 실현가능성 |
| 작동 방식 | 고객이 쓰는 순서나 화면 | 실현가능성의 구체화 |
| 준비 정도 | 어디까지 됐는가, 증빙 | 실현가능성의 현황 |
| 차별점 | 같은 기준의 비교표 | 차별화 |
| 시장 | TAM·SAM·SOM과 산식 | 문제인식의 시장 |
| 사업 방식 | 누구에게 무엇을 얼마에 | 성장전략 |
| 진입 계획 | 첫 고객을 만나는 경로와 일정 | 성장전략 |
| 자금 | 필요한 돈, 쓸 곳, 조달 | 사업비 표 |
| 팀 | 누가 무엇을 맡는가 | 팀 구성 |
| 마무리 | 요청과 다음 단계 | 개요 |

시간이 짧으면 작동 방식·준비 정도를 해결에, 사업 방식을 진입 계획에 합친다. 구분 장은 시간이 넉넉할 때만 넣는다.

## Step 4. 슬라이드 문안

- 제목은 주제어가 아닌 메시지 문장으로 쓴다. "시장 규모"보다 "첫해에 닿을 수 있는 고객은 3만 명".
- 본문 글머리는 장당 3~5줄, 한 줄에 한 가지.
- 숫자를 크게 보여 줄 때는 단위·기준 시점·출처를 같은 장에 적는다.
- 비교표의 기준은 본문과 같게 둔다. 발표에서만 유리한 기준으로 바꾸지 않는다.
- 본문의 조건·한계가 빠져 단정이 세지지 않게 한다. 자리가 없으면 발표 원고에 넣는다.
- 그림·화면·사진은 `[그림: 설명]`으로 자리를 표시하고 사용자가 가진 자료만 계획한다.

## Step 5. 발표 원고

장마다 `핵심 문장 / 보충 / 다음 장으로 넘어가는 말`을 적는다.

- 말로 하는 글이다. 문장을 짧게, 숫자는 한 번에 하나씩.
- 원고의 글자 수로 시간을 가늠한다. 1분에 약 300자를 출발점으로 삼고 사용자의 말 속도로 맞춘다.
- 슬라이드를 읽지 않는다. 슬라이드에 없는 이유와 맥락을 말한다.
- 사용자의 말투를 따른다. 문체 표본이 있으면 [문체 프로파일](voice-profile.md)을 쓴다.

## Step 6. 예상 질문

근거 카드와 본문에서 약한 곳이 질문이 된다.

- 근거 카드에서 `가정`으로 표시한 값
- 경쟁 비교에서 신청자가 뒤지는 기준
- 사업비에서 금액이 큰 비목의 산출 근거
- 팀에 없는 역량
- 맞물림 점검에서 어긋났던 곳

질문마다 답의 근거가 카드 어디에 있는지 적는다. 근거가 없는 질문은 "아직 확인하지 못했다"와 확인 계획을 답으로 준비한다. 지어낸 답을 원고에 넣지 않는다.

## 검수

- 슬라이드와 원고의 모든 수치를 본문과 대조한다. 본문·슬라이드·원고를 `context-audit`의 대상으로 등록하면 불일치를 찾는다.
- 본문에 없는 주장이 생겼는지 `preserve`와 읽기로 확인한다.
- 장 수와 원고 분량이 발표 시간에 맞는지 본다. 최종 판단은 리허설이다.
- 슬라이드 문안에 `[확인 필요]`·`[입력 필요]`가 남아 있으면 발표본이 아니다.
