# 글 유형과 기본 분량

유형은 Step 1에서 목적과 함께 정한다. 아래 분량과 구조는 사용자가 지정하지 않았을 때 쓰는 출발점이며 합격선이 아니다. 사용자가 분량·구조를 정했으면 그 값이 우선한다.

## 유형 기본값

| 유형 | 쓰는 때 | 기본 분량(공백 포함) | 출발 구조 | context |
|---|---|---|---|---|
| 칼럼 | 하나의 관점을 세우고 근거로 받친다 | 1,500~2,500자 | 주장형 또는 장면형 | `column` |
| 문서형 정리 | 메모·자료를 읽기 좋은 순서로 묶는다 | 2,000~4,000자 | 문서형 | `blog`·`official` |
| 분석 기사 | 쟁점의 원인과 영향을 따진다 | 4,000~6,000자 | 데이터형 + 사례형 | `article` |
| 보도자료 | 발표 사실을 매체가 옮겨 쓰게 한다 | 800~1,200자 | 제목·리드·본문·문의처 | `press` |
| 보고서·제안서 | 판단과 다음 행동을 요청한다 | 2,000~5,000자 | 문서형 (요약 선배치) | `official` |
| 뉴스레터 | 구독자에게 한두 가지 주제를 전한다 | 800~1,500자 | 사례형 또는 문서형 | `email` |
| SNS 긴 글 | 피드에서 읽히는 한 편 | 800~2,000자 | 채널 플레이북 참조 | `sns` |
| 강의·발표 원고 | 말로 전달한다 | 1분에 약 300자 | 사례형 (구어) | `blog` |
| 에세이 | 주장보다 대상을 보는 눈을 드러낸다 | 1,500~3,000자 | 장면형 | `column` + [에세이 시선 점검](essay-gaze.md) |

분량 숫자는 운영 기본값이다. 발행 성과가 쌓이면 [성과 기록](performance-log.md) 절차로 조정한다.

## 유형이 명시되지 않았을 때

요청 문장의 신호로 고르고 고른 유형을 한 줄로 밝힌 뒤 진행한다. 신호가 엇갈려 결과가 크게 달라질 때만 묻는다.

| 신호 | 유형 |
|---|---|
| "내 생각은", 의견·관점 중심 | 칼럼 |
| 메모·자료를 주고 "정리해줘" | 문서형 정리 |
| "분석해줘", "원인이 뭐야" | 분석 기사 |
| 발표 주체·일시·문의처가 있음 | 보도자료 |
| "보고", "제안", 결재·승인 대상이 있음 | 보고서·제안서 |
| 겪은 일·장면·감정이 재료의 대부분 | 에세이 |

## 입력 상태와 작성 방식

| 입력 | 방식 | 지킬 것 |
|---|---|---|
| 주제·키워드뿐 | 새로 쓰기 | 사실·수치·경험을 만들지 않고 `[확인 필요]`로 둔다 |
| 메모 세 문장 이상, 초안, 녹취 | 원문 보존 | 문장·어투·서술 순서·구체 사례를 골격으로 유지한다 |
| 확정 아웃라인 | 아웃라인 따라 쓰기 | 항목 순서를 바꾸려면 먼저 제안한다 |

원문 보존에서 사용자가 "새로 써줘"라고 하면 새로 쓰기로 바꾼다. 이때도 원문의 사실과 LOCK은 그대로다.

## 요청 동사와 변경 권한

요청 동사는 편집 강도의 신호다. 인계 계약의 `editorial.structure_change`와 `change_budget_pct`를 이 표로 채운다. 사용자가 강도를 직접 지정하면 그 값이 우선한다.

| 요청 | 강도 | 허용 | 하지 않는 것 |
|---|---|---|---|
| "교정해줘", "맞춤법만" | 보수 | 맞춤법·띄어쓰기·명백한 오기 | 문장 구조 변경, 문단 이동 |
| "다듬어줘", "윤문해줘", "정리해줘" | 기본 | 진단된 구간의 문장 정리, 접속 보강 | 문단 재배치, 새 내용 추가 |
| "다시 써줘", "구조까지 봐줘" | 적극 | 문장 교체, 승인받은 재배치 | 원문에 없는 사실·주장 추가, 양태 변경 |

어느 강도에서도 "될 수 있다"를 "된다"로 바꾸는 식의 확신도 변경은 하지 않는다. 가능성·조건·추정은 의미의 일부다. 구조를 바꿔야 한다고 판단하면 수정본과 따로 "구조 변경 제안"으로 낸다.
