# 도입과 마무리

도입은 독자가 계속 읽을지 정하는 자리이고 마무리는 글이 남기는 판단을 정하는 자리다. 아래 유형은 고르는 목록이지 순서대로 채우는 틀이 아니다. 자료에 없는 장면·수치·경험으로 도입을 만들지 않는다.

## 도입 유형

| 유형 | 방식 | 필요한 재료 |
|---|---|---|
| 판단 선언 | 글의 결론을 첫 문장에 둔다 | 본문이 받칠 근거 |
| 장면 | 제공된 구체 장면에서 시작한다 | 사용자가 준 장면·관찰 |
| 질문과 한 줄 답 | 독자가 가진 질문을 쓰고 바로 답한다 | 답의 근거 |
| 통념과 어긋나는 사실 | 흔한 믿음과 다른 사실을 내놓는다 | 출처가 있는 사실 |
| 실물 예고 | 글에서 얻을 것을 그대로 밝힌다 | 본문에 실제로 있는 목록·양식 |
| 증상 진단 | 독자가 겪는 문제를 짚고 원인을 다시 본다 | 원인을 뒷받침할 자료 |
| 수치 | 숫자 하나와 그 뜻을 먼저 쓴다 | 출처·기준일이 있는 수치 |

고르는 기준은 두 가지다. 첫 문장만 읽어도 글의 주제를 알 수 있는가. 첫 문장의 약속을 본문이 지키는가.

후보를 요청받으면 서로 다른 유형으로 최대 세 개를 낸다. 같은 유형의 낱말만 바꾼 후보는 내지 않는다.

## 피할 도입

`channel-check`가 CH-9로 올리는 후보와 사람이 볼 항목이다. 실제 기능이 있으면 유지한다.

| 유형 | 예 | 유지 조건 |
|---|---|---|
| 예고 | "오늘은 ~에 대해 알아보겠습니다" | 강의 원고처럼 순서 안내가 필요한 글 |
| 인사말 | "안녕하세요, ○○입니다" | 뉴스레터·공지처럼 관계가 먼저인 글 |
| 사전식 정의 | "○○이란 ~을 말한다" | 용어 정의가 글의 목적일 때 |
| 참여 요구 | "좋아요와 공유 부탁드립니다" | 도입에서는 유지하지 않는다 |
| 감탄 | "정말 놀라운 결과였습니다" | 원문 필자의 말투일 때 |
| 소식 옮기기 | "A사가 B를 발표했습니다"로만 시작 | 속보 전달이 목적일 때 |

## 마무리 유형

| 유형 | 맞는 글 |
|---|---|
| 구체적 권고 | 보고서, 방법 안내 |
| 다음 행동 | 공지, 뉴스레터, 제안서 |
| 적용 범위와 제한 | 분석 기사, 데이터형 글 |
| 남은 쟁점 | 칼럼, 해설 |
| 판단 한 문장 | 칼럼, SNS 긴 글 |
| 장면으로 돌아가기 | 에세이, 장면형 글 |
| 바로 쓸 예시 | 방법 안내, 자료 배포 |

본문을 다시 줄여 말하는 요약은 긴 문서형 글에서만 쓴다. 한 사람이 쓴 글이 매번 같은 방식으로 끝나면 [문체 프로파일](voice-profile.md)의 이탈 징후가 아니라 개인 반복이므로 Editorial Audit에서 다룬다.

## 제목

- 제목은 본문에 있는 판단·대상·조건으로 만든다. 본문에 없는 약속을 넣지 않는다.
- 후보는 요청받았을 때 3~5개. 질문형·대상+조건형·판단형처럼 형태를 달리한다.
- 숫자를 넣을 때는 본문 항목 수와 맞는지 대조한다.
- 채널별 길이는 [채널 플레이북](channel-playbooks.md)과 `channel-check --title`로 확인한다.
