# 보호 구간과 잔존 패턴 계약

윤문 전후에 다음 구간은 문자열 단위로 대조한다.

- YAML frontmatter
- fenced code와 inline code
- blockquote와 직접 인용
- Markdown 표 행
- URL, 파일 경로, 헤딩과 각주
- 숫자, 영문 기술 용어, 불릿·표·코드 구조 개수

보호 구간을 고쳐야 한다면 일반 윤문에 섞지 말고 별도 제안으로 분리한다. `preserve --strict`는 보호 구간 변경, 의미 표지 변화, 새 P0/P1 패턴 증가가 있으면 실패한다.

진단 단계에서는 보호 구간 내부의 상투 표현을 세지 않는다. 문서가 AI 문체를 설명하기 위해 인용한 나쁜 예문을 저자 문체로 오인하지 않기 위해서다.
