# 번역 스킬을 위한 대외 자료 조사 — 2026-10-21

## 조사 결과와 읽는 법

논문, 공식 지침, 연구자 공개 저장소, 언론 보도를 함께 검토했다. 각 항목의 **확인 내용**은 출처의 주장이고 **적용안**은 우리 스킬에 대한 설계 제안이다. 자료를 찾았다는 것과 기능을 구현하거나 성능을 입증했다는 것은 구분한다. 아래 적용안은 코드 변경 완료 목록이 아니다.

가장 직접적인 보강점은 네 가지다. 의미 정확도와 자연스러움을 따로 평가하고, 허용되는 용어 변형을 남기며, 한국어 높임말과 화자의 관계를 보존하고, 후편집으로 새로 생긴 오류를 다시 대조한다. 단어 출현 횟수나 수정량은 검토 순서를 정하는 보조값으로 둔다.

언론은 실제 도입 절차와 현장 쟁점을 파악하는 자료로 사용한다. 특정 회사의 발표·번역가 인터뷰를 통제된 품질 실험과 동일하게 취급하지 않는다. 논문의 언어쌍·장르·평가 조건이 다르면 결과를 한국어 전체로 확대하지 않는다. 초록만 확인한 자료는 별도로 표시했다.

## 1. 공식 평가 기준과 번역 지침

### R01. MQM Council — Scoring Models, Error Typology

- 자료: [점수 모델](https://www.themqm.org/mqm-pillars/the-mqm-scoring-models/), [오류 분류](https://new.themqm.org/mqm-pillars/typology/).
- 확인 범위: 공식 웹 본문. 열람 2026-10-21.
- 확인 내용: 오류 유형과 심각도를 분리한다. 심각도는 문서의 목적에 미치는 영향에 따라 정하며, 허용되는 번역의 선호 차이는 Neutral로 둘 수 있다. 0·1·5·25 가중치는 예시이고 평가 사업에 맞춘 조정과 보정이 가능하다. 정확도는 원문 대응을 뜻하며 외부 세계에 대한 사실 검증과 동일하지 않다.
- 적용안: 현재의 보존 검사에서 `critical`로 표시하는 차단 조건과 사람이 판단하는 MQM Critical을 구분해 설명한다. 반복 횟수가 높다고 실제 의미 오류가 자동으로 심각해지는 것으로 보고하지 않는다. `검토 후보/확인된 오류/허용 표기/보류`를 기록할 수 있게 한다.

### R02. European Commission — Revision and post-editing

- 자료: [공식 안내](https://knowledge-centre-translation-interpretation.ec.europa.eu/en/content/revision-and-post-editing).
- 확인 범위: 공식 웹 본문. 열람 2026-10-21.
- 확인 내용: 사람 번역의 감수(revision)와 기계번역의 후편집(post-editing)을 구분한다. light는 기본 정확성과 이해 가능성, full은 더 명료하고 다듬어진 결과를 목표로 한다.
- 적용안: 작업을 시작할 때 이해용·배포용·출판용 목적을 적고 목표 품질을 정한다. light/full을 글자 변경률의 고정 구간으로 정의하지 않는다. 변경률은 별도 증적이다.

### R03. Microsoft — Korean Localization Style Guide

- 자료: [공식 스타일 가이드 목록](https://learn.microsoft.com/en-us/globalization/reference/microsoft-style-guides), [확인한 한국어 PDF](https://download.microsoft.com/download/5/b/6/5b62389f-4e3b-4c77-bc18-94efba2fa7bb/kor-kor-StyleGuide.pdf).
- 확인 범위: 55쪽 PDF의 목차와 관련 절. 35~36쪽의 엔터티 토큰, 37~38쪽의 오류 메시지·마침표 예외 확인. 파일 메타데이터를 공식 발행일로 해석하지 않았다.
- 확인 내용: 제품의 독자와 의도를 반영하며, 엔터티 토큰은 일반적으로 번역하지 않되 표시용 예시에는 개발자 설명에 따른 예외가 있다. 오류 메시지는 한국어 문장 형태에 따라 원문과 다른 마침표 처리가 가능하다.
- 적용안: UI의 실제 토큰과 설명용 예시를 구분하는 `translate/no_translate/context_note` 규칙을 둔다. 콜론·마침표 수가 달라졌다는 이유만으로 번역 오류를 확정하지 않는다. Microsoft의 브랜드 문체는 해당 제품용 지침이므로 모든 한국어 원고에 강제하지 않는다.

## 2. 한국어와 문서 맥락에 직접 도움이 되는 논문

### R04. Park·Padó, LREC-COLING 2024 — Multi-Dimensional Machine Translation Evaluation

- 자료: [논문](https://aclanthology.org/2024.lrec-main.1024/), [PDF](https://aclanthology.org/2024.lrec-main.1024.pdf), [연구자 저장소](https://github.com/DojunPark/multidimensional_MTE).
- 확인 범위: 초록, 본문 데이터·평가 설명, 한계, README.
- 확인 내용: 영어→한국어 1,200개 평가 항목을 제공하고 정확도·유창성·문체를 분리한다. 연구에서 참조 번역 유무의 유불리는 평가 차원마다 달랐다.
- 적용안: 우리 감사 결과도 종합 점수 하나보다 오류 차원을 먼저 보여 준다. 한국어 회귀 평가 자료 후보로 삼되 학습·검증·평가 자료를 섞지 않는다.
- 범위: 특정 언어쌍과 당시 모델·자료에 대한 연구다. 공개 저장소라는 이유로 데이터·모델의 이용 조건이 모두 같다고 가정하지 않고, 재배포나 상업적 사용 조건은 별도 확인한다.

### R05. Hwang 외, LREC-COLING 2024 — Kosmic

- 자료: [논문](https://aclanthology.org/2024.lrec-main.870/).
- 확인 범위: 초록·서지. 모델을 실행하거나 자체 재현하지 않았다.
- 확인 내용: 한국어 텍스트의 유사성을 평가할 때 의미뿐 아니라 높임말과 말투도 고려한다.
- 적용안: 같은 뜻이라도 `확인해`와 `확인해 주세요`를 무조건 동등하게 처리하지 않는다. 문서 전체의 종결형과 별개로 화자·청자·인용·대화 상황을 기록한다.
- 범위: 한국어 유사성 연구이며 모든 번역 품질을 평가하는 도구는 아니다.

### R06. Ahrii Kim, WMT 2025 — Context Is Ubiquitous, but Rarely Changes Judgments

- 자료: [논문](https://aclanthology.org/2025.wmt-1.5/), [PDF](https://aclanthology.org/2025.wmt-1.5.pdf).
- 확인 범위: 초록, 본문 데이터 구성·사람 평가·문맥 분류 설명.
- 확인 내용: 영어→한국어 자료를 바탕으로 문맥 평가의 재현성을 검토한다. 필터링한 38개 문서·809문장을 평가하며, 문맥이 존재한다는 것과 실제 판단을 바꾼다는 것을 구분한다. 평가자 간 판단 차이도 분석한다.
- 적용안: 문장을 고칠 때 어떤 이웃 문장·문서 정보가 판단을 바꿨는지 근거를 남긴다. ‘문맥을 더 넣었다’ 자체를 개선 실적으로 세지 않는다. 지시 대상·호칭·양태·논리 연결의 변화가 실제 수정에 영향을 주었는지 기록한다.
- 범위: 필터링된 영어→한국어 자료와 평가 설정의 결과다. 모든 문서에 적용할 고정 문맥 비율이나 개선율을 뜻하지 않는다.

### R07. Dahan 외, AMTA 2026 / arXiv 2026-09 — Variation Matters

- 자료: [저자 공개 논문 페이지](https://arxiv.org/abs/2609.08779).
- 확인 범위: 초록·서지. 본문 HTML은 열리지 않아 초록 범위만 사용했다.
- 확인 내용: 영어→프랑스어 과학 문서에서 허용되는 용어 변형까지 불일치로 벌점화하는 문제를 다룬다. 용어집 제약이 정확도·일관성을 높이면서 타당한 변형을 억제할 수 있다고 보고한다.
- 적용안: 용어집의 권장어·허용어·금지어를 구분하고, 약칭·정식 명칭·설명형 표현의 허용 범위를 명시한다. 같은 원어가 문맥에 따라 다른 개념을 뜻하는 경우를 무조건 하나로 통일하지 않는다.
- 범위: 영어→프랑스어 결과이며 한국어 효과는 별도 평가가 필요하다.

### R08. Hazem 외, LREC 2026 — CoTERM

- 자료: [학회 논문 페이지](https://lrec.elra.info/lrec2026-main-682).
- 확인 범위: 학회 초록·서지.
- 확인 내용: 용어 번역을 정확도, 문서·말뭉치 수준 일관성, 분야에 적절한 변형 관점에서 평가한다. 일반 번역 지표와 용어 처리 성능은 같지 않을 수 있다.
- 적용안: 전체 문장이 자연스럽다는 평가와 분야 용어가 맞는지에 대한 검사를 별도로 보고한다. 빈도가 높은 역어가 곧 올바른 역어라는 규칙을 쓰지 않는다.
- 범위: CoTERM을 설치하거나 그 점수를 산출한 것이 아니다.

### R09. Gerrits 외, EAMT 2026 — Creativity Bias

- 자료: [논문](https://aclanthology.org/2026.eamt-1.43/).
- 확인 범위: 초록·서지. 기존 `translation-fidelity.md`의 근거와 재대조했다.
- 확인 내용: 문학 번역의 창의성 평가에서 자동 지표·LLM 심사와 전문 번역가의 판단이 어긋날 수 있음을 보고한다.
- 적용안: 모호성·의도된 반복·문화적 표현을 ‘더 매끈하게’ 바꾸는 수정에는 원문 근거를 요구한다. 문학 번역의 최종 채택을 자동 점수 하나로 결정하지 않는다.

### R10. 한승희·강동희, 통번역학연구 2022 — 한·노 번역과 후편집 비교

- 자료: [KCI 논문 정보·초록](https://www.kci.go.kr/kciportal/ci/sereArticleSearch/ciSereArtiView.kci?sereArticleSearchBean.artiId=ART002815215).
- 확인 범위: 초록·서지. 유료 전문을 열람한 것으로 표현하지 않는다.
- 확인 내용: 감수·후편집 후 품질이 개선됐지만 일부 오류 유형은 늘었고, 명시화가 과도한 개입으로 평가된 사례도 있었다.
- 적용안: 초벌→수정본에서 없어진 오류와 새로 생긴 오류를 나누어 기록한다. 원문에 없는 주어·해설·감정을 추가한 뒤 자연스러움만으로 합격시키지 않는다.
- 범위: 한·노 번역 사례 연구이며 현재 LLM 전체의 성능을 말하지 않는다.

### R11. google-research/mt-metrics-eval

- 자료: [저장소](https://github.com/google-research/mt-metrics-eval).
- 확인 범위: README. 설치·자료 다운로드·점수 산출은 하지 않았다.

- 적용안: 스킬을 고도화한 뒤 동일한 평가 세트에서 전후 결과를 비교한다. 버전·언어쌍·자료·평가자·설정과 실패 사례를 함께 남긴다.
- 범위: 도구를 쓴다는 이유로 한국어 품질이 검증되는 것은 아니다. 각 자료의 포함 언어와 사용 조건을 먼저 확인한다.

### R12. BYU-TRG-Team/mqm-scorecard

- 자료: [저장소](https://github.com/BYU-TRG-Team/mqm-scorecard).
- 확인 범위: README.
- 확인 내용: 프로젝트별 원문·번역문, 평가 기준, 선택적인 요구사항을 묶고 결과를 JSON으로 기록하는 구조를 제공한다.
- 적용안: 번역 목적과 요구사항을 오류 목록과 함께 넘기는 인계 양식을 만든다. 평가 기준이 달라진 문서의 점수를 그대로 순위 비교하지 않는다.
- 범위: 구현 구조만 참고한다. 저장소에 기재된 서버 구성이나 오래된 의존성을 우리 스킬의 필수 설치 항목으로 가져오지 않는다.

R04의 연구자 저장소는 한국어 평가 자료 후보이고, R11은 지표 검증 도구, R12는 평가 작업 구조의 참고다. 서로 다른 역할을 동일한 ‘번역 도구 추천’으로 묶지 않는다. 기존 `references/github-writing-research-20261021.md`의 translation-agent·COMET·BabelDOC 등 조사도 함께 참고한다.

## 5. 장르별 검토 항목 — 우리 적용안

아래는 위 자료를 종합한 설계안이며 개별 논문의 실험 결과를 그대로 옮긴 목록이 아니다.

- **기술문서·UI:** 용어와 실제 화면 명칭, 식별자·자리표시자, 오류 메시지의 문장/구 단위, 예시 문자열 여부를 확인한다.
- **공공·업무 문서:** 기관명·직함·기준 시점·수치 단위, 의무/권고/가능성, 확정/예정 상태를 구분한다. 공식 번역이나 제공된 용어집이 있으면 우선 근거로 둔다.
- **기사·인터뷰:** 화자와 인용, 사실과 해석, 의도된 불확실성, 시간·주체·지시 대상을 보존한다.
- **문학:** 시점·인물 관계·정조·모호성·반복을 장면 단위로 확인한다. 어색함을 모두 제거하는 목표를 세우지 않는다.
- **마케팅·SNS:** 독자와 브랜드 문체를 따르되 원문에 없는 효능·수치·추천·성공담을 만들지 않는다.
- **자막·음성:** 길이·표시 시간·화자 전환을 추가로 확인한다. 이번 조사로 자막 전용 임계값까지 검증한 것은 아니다.

## 6. 우선순위와 평가 계획

### 먼저 반영할 지침

1. 작업 인계에 언어 방향·독자·장르·이해용/배포용/출판용 목적·용어집·화자 관계·문맥 범위를 명시한다.
2. 단일 권장 역어 외에 허용 변형과 사용 조건을 기록한다. 사례별 수정 이유와 유지 이유를 남긴다.
3. 기계적 차단 조건, 실제 오류의 심각도, 탐지 확신도, 사람의 채택 결정을 분리한다.
4. 원문·초벌·후편집본을 함께 보존하고 새로 생긴 오류를 검사한다.
5. 문맥이 필요하면 어떤 문맥 때문에 판단이 바뀌었는지 기록한다. 관계를 추측으로 확정하지 않는다.

### 평가 세트 설계안

기술/UI·업무/공공·기사·문학 네 분야에 정확도 오류, 용어 오류, 말투 변화, 정상적인 변형, 문맥 의존, 자리표시자 예외를 섞은 자체 작성 사례를 만든다. 총량 목표와 평가자의 수는 실행 전에 정하고, 보정용과 최종 평가용을 분리한다. 오탐·누락·새 오류·검토 시간과 사람 평가자의 불일치를 함께 보고한다. 외부 자료를 베껴 평가 원고를 만들지 않는다.

수치·문자열 검사 테스트가 통과했다고 번역 품질이 향상됐다고 발표하지 않는다. 외부 논문의 효과 크기나 상관계수를 우리 스킬의 성능으로 표시하지 않는다.
