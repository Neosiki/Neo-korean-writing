# 접속 부사 선택형 윤문 규칙

## 원칙

`그러나` `따라서` `또한` `그러므로` `한편` 같은 접속 부사는 AI 글의 증거가 아니다. 문장 사이의 대조나 인과를 분명하게 해야 하는 자리에서는 남긴다. 앞뒤 문장만으로 관계가 충분히 전달되고 같은 표지가 반복될 때만 축약 후보로 본다.

## 진단 기준

`python3 scripts/krh.py connectives 원문.md`는 문장이나 문단의 시작에 놓인 접속 부사를 찾아 위치와 반복 횟수를 보여 준다.

| 상황 | 처리 |
|---|---|
| 한 번 등장하고 실제 대조·인과·양보를 표시함 | 유지 |
| 같은 접속 부사가 문단에서 반복됨 | 후보로 표시 |
| 여러 접속 부사가 짧은 구간에 밀집됨 | 후보로 표시 |
| 논문·보고서에서 논리 관계를 명시해야 함 | 유지 우선 |
| 에세이·SNS에서 앞뒤 문장만으로 의미가 전달됨 | 삭제 또는 문장 재구성 검토 |

## 예시

### 유지하는 경우

> 처음에는 별생각 없었다. 그러나 며칠 뒤 다시 읽었다.

`그러나`가 한 번 나오고 앞뒤의 시간적 변화와 대조를 연결하므로 진단 결과는 `유지 검토`다.

### 축약을 검토하는 경우

> 그러나 첫 장면은 달랐다. 그러나 결과는 같았다. 또한 기록도 남겼다.

같은 표지가 반복되고 세 문장에 접속 표지가 몰려 있으므로 후보로 표시한다. 다만 실제 글을 고칠 때는 표지를 모두 지우지 말고 한 문장은 남길지 문장 순서를 바꿀지 먼저 판단한다.

### 선택형 실행

```bash
python3 scripts/krh.py connectives draft.md --json
python3 scripts/krh.py connectives draft.md --remove-redundant --json
```

`--remove-redundant`는 자동 채택 명령이 아니다. 결과의 `rewritten`을 원문과 비교하고 대조·인과·양보·범위가 보존됐는지 확인한 뒤 사용한다.

## 제한

이 규칙은 문장 시작 위치와 반복량을 이용한 후보 탐지다. 문장의 논리 관계를 완전히 판정하지 않으며 접속 부사 사용만으로 작성 주체나 생성 방식을 판별하지 않는다. 최종 윤문은 장르와 필자의 문체를 함께 읽어 결정한다.
