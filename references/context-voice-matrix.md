# Context와 Voice 분리

Context는 장르상 무엇을 허용할지 정하고, Voice는 문장이 어떻게 들릴지 정한다. 두 축을 섞지 않는다.

## Context

| context | 완화 항목 | 강화 항목 |
|---|---|---|
| `column` | 의도적 반복·긴 문장 | 상투적 결론·근거 없는 과장 |
| `article` | 기사 관례의 제한적 익명 출처 | 출처 없는 단정·판단 혼입 |
| `press` | 일부 보도자료 관례 표현 | 검증되지 않은 최상급·성과 수치 |
| `official` | 관공서 용어·목록 | 책임 주체 소실·중복 명사화 |
| `technical` | 코드·표·기술 용어·명령형 | 용어 불일치·모호한 주체 |
| `blog` | 필자 의견·다소 자유로운 호흡 | 공식적 도입·상투적 CTA |
| `sns` | 짧은 문장·일부 장식·목록 | 해시태그·후크·감정 과잉 |
| `email` | 인사와 요청 구조 | 과장·모호한 다음 행동 |

## Voice

- `preserve`: 기본값. 원문의 종결, 어휘 온도, 문장 길이 편차를 유지한다.
- `yoon-reporter`: 사용자가 윤기자 프로파일을 요구할 때만 적용한다.
- `professional`: 주장을 먼저 쓰고 요청과 근거를 명시한다.
- `warm`: 원문에 이미 있는 독자 호명과 배려를 살린다.
- `blunt`: 완곡한 예고를 줄이고 결론을 앞에 둔다.
- `technical`: 용어 정의와 절차 정확성을 우선한다.

Voice는 원문에 없는 1인칭, 감정, 일화, 반대편 주장, 수치나 사례를 만들 권한이 아니다.
