# GitHub 조사와 적용 결정 — 2026-10-21

저장소의 README·설계 문서를 확인했다. 아래는 외부 코드를 복사하거나 실행한 목록이 아니라 개념을 검토한 기록이다. 별 개수는 한국어 품질·실사용자 수·최근 채택을 증명하지 않으므로 채택 근거로 쓰지 않았다. 검색 시점과 원문 개정 시점은 다를 수 있다. 구현은 Python 표준 라이브러리로 별도 작성했다.

## 번역 감수

- [Andrew Ng translation-agent](https://github.com/andrewyng/translation-agent): 번역→비평→수정 흐름을 기존 v8 프롬프트와 대조했다. 저장소 스스로 데모 성격과 성능 편차를 알리고 있어 자동 품질 향상을 약속하지 않는다. 별도의 비평을 추가할 때는 정확도·누락·용어·문체를 나누고 수정 우선순위를 정한다.
- [COMET](https://github.com/Unbabel/COMET): XCOMET의 오류 심각도·오류 위치 보고를 참고했다. 현재 v8의 MQM식 분류와 휴리스틱 가중치는 사람이 평가한 MQM 점수나 COMET 점수가 아니다. 모델 가중치 다운로드·비용·모델별 조건을 검토해야 하므로 신경망 평가를 기본 의존성으로 넣지 않았다.
- [BabelDOC](https://github.com/funstory-ai/BabelDOC): 용어집과 문서 구조를 함께 다루는 방향을 참고했다. 해당 구간에 필요한 용어를 골라 전달하는 원칙을 채택했다. PDF 번역 시스템의 성능이나 특정 언어쌍 성과를 한국어 윤문 성능으로 옮겨 주장하지 않는다.
- [Translate Toolkit](https://github.com/translate/translate): 번역 QA, 용어 추출과 충돌 점검의 역할 분리를 참고했다. 많이 나타난 단어를 바로 권장 역어로 확정하지 않는다. 코드·검사 목록을 그대로 가져오거나 GPL 코드를 패키지에 포함하지 않았다.

## 문서 맥락과 문체

- [Vale](https://github.com/vale-cli/vale): 마크업을 고려한 검사 범위와 규칙 기반 편집을 참고했다. 코드·링크 주소를 일반 문장처럼 교정하지 않고 보이는 링크 글자는 확인한다. 이번 간이 마스킹이 Vale 전체 파서를 대체한다고 보지 않는다.
- [Docling의 chunking 설계](https://github.com/docling-project/docling/blob/main/docs/concepts/chunking.md): 문서 조각에 구조·출처 맥락을 붙이는 관점을 참고했다. 문서 ID·절·행·원본 해시를 결과에 남긴다. Docling이나 OCR 모델을 필수 설치하지 않는다.
- [blader/humanizer](https://github.com/blader/humanizer): 반복된 문장 틀을 문맥과 함께 보는 접근과 과도한 재작성 방지를 대조했다. 기존 A~O 진단에 무작정 금지어를 보태지 않았다. 저자 판별, ‘AI 티 0건’, 특정 탐지기 회피를 보장하지 않는다. 인용·수치·고유명사를 보존하고 장르에 맞는 표현은 유지한다.

## 실제 반영

1. 기존 미게시 v8 커밋의 MQM식 심각도·용어집·누락·잔류·자리표시자 검사를 보존했다.
2. 설치형 CLI에서 빠졌던 `--glossary`·`--strict` 전달과 TSV 패키징을 보완했다.
3. 허용 영어 용어 하나가 문장 전체의 잔류 경고를 가리는 문제를 고쳤다. 링크 글자는 검사하고 틸드 코드 블록은 제외한다.
4. 명시한 파일만 검사하는 `context-audit`를 추가했다. 용어·개체 별칭·주장과 출처를 연결하며, 동명이인·시점 차이·범위 차이는 자동 병합하지 않는다.
5. 사람의 판단이 필요한 후보와 기계적으로 확인할 수 있는 인용 누락을 구분한다. 자동 웹 검증·전역 치환·외부 전송·임베딩 저장은 추가하지 않았다.

한국어 품질의 향상 정도는 실제 장르별 원고와 번역문 평가가 더 필요하다. 이번 회귀 테스트는 지정한 동작과 오탐 방지 조건을 확인하며, 번역 품질 벤치마크를 대신하지 않는다.
