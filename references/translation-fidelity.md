# v7 번역 후편집·문학 번역 충실성 레인

v6의 `preserve`는 숫자·인용·영문 용어를 잠그는 표면 게이트였다. v7에서는 번역문을 다룰 때 **표면 잠금 → 구조 대조 → 의미 위험 플래그 → 사람 검토**의 순서를 별도 레인으로 둔다. 이 도구는 번역 품질을 자동 판정하지 않는다. 자동 지표가 유창성은 높게 보이지만 충실성·개체명·문화어·생략을 놓칠 수 있다는 2025년 평가들의 공통 결론을 반영한 것이다.

## 실행

```bash
python3 scripts/translation_audit.py 원문.md 번역문.md --direction en-to-ko --json
python3 scripts/translation_audit.py 원문.md 번역문.md --direction en-to-ko --literary
python3 scripts/korean_writing.py translation-audit 원문.md 번역문.md --direction en-to-ko --strict
python3 scripts/korean_writing.py translation-audit 원문.md 번역문.md --direction en-to-ko --glossary 용어집.tsv --json
```

`pass`는 표면·구조 위험이 발견되지 않았다는 뜻이지, 의미가 자동으로 확정됐다는 뜻이 아니다. `warn`은 사람이 대조해야 할 위험 신호, `hold`는 숫자·URL·코드·약어·링크 대상이나 문서 구조가 달라져 채택을 멈춰야 하는 상태다.

### 용어집 형식

`templates/translation-glossary.tsv`를 복사해 쓴다. 한 줄에 `원어 ⇥ 권장 역어|허용 변형 ⇥ 금지 역어(선택) ⇥ strict|flex(선택) ⇥ 사용 문맥(선택)`을 적는다. 첫 역어가 권장어이고 나머지는 허용 변형이다. 4열을 비우면 flex다. JSON(`{"원어": ["역어"]}` 또는 `[{"source","target","forbid"}]`)도 읽는다. 용어집 검사는 원어가 원문에 있을 때만 적용된다.

### LLM 심사 점수를 합격 근거로 쓰지 않는다

EAMT 2026의 「Creativity Bias」 연구(Gerrits·van Noord·Guerberof Arenas)는 문학 번역 데이터를 전문 번역가가 창의성 기준으로 주석한 뒤 자동 지표와 LLM 심사 점수를 비교했다. 두 방식 모두 전문가 판단과 상관이 낮았고, LLM 심사는 기계번역 쪽을 선호하며 창의적이고 문화적으로 적절한 선택에 낮은 점수를 줬으며, 시처럼 문학성이 짙을수록 더 나빠졌다. 이 레인에서 쓰는 규칙은 다음과 같다.

1. `--literary` 번역의 최종 판단은 LLM 점수가 아니라 장면 단위 사람 검토로 한다.
2. 비평 단계에서 LLM이 "더 매끄럽다"는 이유로 낸 수정은 창의적 선택(creative shift)을 오류로 오인한 것일 수 있다. 원문에 근거가 없는 평탄화는 롤백한다.
3. 자동 지표·MQM 휴리스틱 점수는 후보 정렬용이다. 문학 문서에서는 점수가 낮은 번역이 더 나쁜 번역이라는 뜻이 아니다.

출처: https://aclanthology.org/2026.eamt-1.43/

## 추가 검토 경로와 숫자 표기

### 기사 번역 점검 v9.3

10월 19~21일의 짧은 기사 6구간으로 확인한 개선과 의미 검토 범위는 [기사 번역 검토](news-translation-review.md)에 있다. 네 자리 연도형 값(1000~2999)의 년 접미와 percentage points 별칭을 정규화한다. `%`와 `%p`는 구분하고 바뀐 연도는 계속 잡는다. 연도형 숫자의 실제 뜻이나 조사 대상과 숫자의 연결은 자동 판정하지 않는다. 출처·상대 날짜·주장·부인·조사 집단은 원문 위치를 붙여 별도로 검토한다.

문체를 누구의 선택으로 볼지, 막힌 구절을 어디까지 조사할지, 정보의 공개 순서와 쉼을 어떻게 대조할지는 [번역가 외부 자료 3선](translator-craft-research-20261021.md)과 `prompts/translation-craft-review.md`를 참고한다. 한 문장의 특성을 번역가 개인의 습관으로 확정하지 않는다.

### 현지화 대응 v9.5

Grok v10.2 제안을 v9.4.1 위에 통합했다. 수량 표기와 현지화 약어 조정은 `surface_lock.reconciled`와 FID-14 검토 후보에 남긴다. PM·MP는 정치 문맥이 있는 등장 횟수까지만 조정한다. 초벌 대비 `baseline_delta`도 같은 기준으로 비교한다.

`23:00`과 `오후 11시`, `00:00`과 `오전 12시`는 시·분을 묶은 같은 값으로 본다. 오전·오후 반전, 모호한 `11시`, 분의 뒤바뀜은 일치로 처리하지 않는다. 괄호 안 마일·통화·GMT 생략은 자동 면제하지 않는다. 정보 삭제가 편집상 필요한지는 사람이 정한다. 기사 자료와 집계의 확인 범위는 [외부 자료 인계 검토](foreign-media-corpus-20261021.md)에 있다.

### 숫자 표기 정규화 v9.4

v9.2의 단위 별칭 위에 값이 같은 표기를 맞추는 층을 얹었다. `1.5 billion`과 `15억`, `24 to 36`과 `24~36`, `years`와 `년`, `years old`와 `세`를 대조한다. `명·개·건·회`는 값만 비교하므로 대상이 사람인지 물건인지는 사람 검토가 필요하다. 통화 환산과 소수점 로캘은 변환하지 않는다. 월 이름만 있는 경우와 한국어 `3월`은 별도로 짝짓지 않는다.

v9.4.1에서는 양쪽의 인식된 날짜가 모두 연도를 명시했을 때 연도와 월·일의 결합도 잠근다. 날짜의 순서 변경은 허용하지만 두 날짜의 연도만 뒤바꾸면 hold다. 일부 날짜가 연도를 생략한 경우에는 기존처럼 연도·월일을 따로 세며 공유 연도를 추정하지 않는다. 코드 블록은 숫자 분석에서 제외해도 원문 내용 전체를 잠그고, 한국어 큰 수의 음수 부호도 보존한다.

마일·파운드·피트·인치·온스·화씨 환산은 계산값과 번역문의 표시 정밀도를 대조한다. 기존의 5%·섭씨 1.5도 허용은 제거했다. 허용 오차는 번역문 마지막 표시 자리의 절반이며, 예를 들어 소수 둘째 자리면 0.005다. 맞으면 계산값·차이·오차를 `verified_conversions`로 보고하고 review로 남긴다. 다른 항목에 누락이 있으면 여전히 hold다. 환산 계수·온도식은 [NIST SP 811 부록 B.9](https://www.nist.gov/pml/special-publication-811/nist-guide-si-appendix-b-conversion-factors/nist-guide-si-appendix-b9)를 기준으로 확인했다. 이 반올림 판정은 스킬의 운영 규칙이며 NIST의 번역 검수 기준이라는 뜻이 아니다. 온도식은 절대 온도 기준이며 온도 차이·각도·화폐 파운드 같은 문맥은 별도 확인한다. 같은 값이 서로 다른 대상에 연결되는 의미 오류까지 검증하지 않는다.

환산은 통상 마일·국제 피트·상용 파운드·상용 온스 기준이다. 명시적인 `nautical mile`과 `pounds sterling`은 각각 해리·통화로 분리해 마일·무게 파운드로 환산하지 않는다. 한정어 없이 쓰인 파운드의 의미, 측량 피트, 트로이온스 같은 다른 기준은 사람이 확인한다.

### 숫자·단위 표면 잠금 v9.2

`1,348 won`과 `1,348원`은 `1348원`으로 대조한다. `percent/per cent/퍼센트/%`, 일부 SI 단위의 영문·한국어 명칭도 명시된 별칭만 정규화한다. 세 자리씩 묶인 천 단위 쉼표와 단위 앞 공백은 맞추지만 값·부호·단위·반복 횟수는 지우지 않는다. `10 m`와 `10 cm`, `-5%`와 `5%`, `2억 원`과 `2만 원`은 여전히 다른 토큰이다. 결과의 숫자 `value`는 정규화된 비교 키이며 원문 인용이 아니다.

통화 환산, km↔m 환산, 영문 숫자 단어, 단위 앞 통화 기호, 한국어 수사, 날짜 순서 변환, 소수점 쉼표 해석은 이 개선 범위 밖이다. 예를 들어 `10 km`와 `10000 m`가 같다는 판단은 사람이 한다. 목록에 없는 단위의 의미 일치도 자동 인증하지 않는다. 이는 번역 감사 전용 보정이며 같은 언어 윤문의 `preserve` 보존 규칙은 바꾸지 않는다.

## 문학 모드: 데보라 스미스를 어떻게 참고할 것인가

데보라 스미스는 번역 서비스가 아니라 한국문학 번역가다. 따라서 문학 모드는 그의 문장을 복제하는 기능이 아니라, 문학 번역에서 **독자 친화적 재구성과 원문 충실성 사이의 긴장**을 검토하는 대비 기준이다.

### 확인된 기법과 방법

- 작품 전체를 먼저 읽고, 막히는 구절은 일단 진행한 뒤 맥락을 다시 보며 해결한다. 『채식주의자』 작업을 설명한 인터뷰에서 전체 독서와 구간별 작업, 재방문 방식이 언급된다.
- 작가에게 질문을 보내고 작품의 문화적 맥락을 대화로 확인한다. 『소년이 온다』는 역사·문화 맥락을 더 많이 대화해야 했다고 설명했다.
- 한국어의 모호성·반복·중복을 영어의 정밀성·간결성에 맞춰 재구성하며, 줄거리만 옮기기보다 운율·분위기·목소리를 우선한다.
- 장면을 독자가 붙잡을 수 있도록 감각적이고 구체적인 이미지를 택한다. 모호한 비유를 구체화한 사례는 번역자의 해석이 개입하는 지점으로 검토해야 한다.

### 문체와 주요 사용 어휘

인터뷰에서 반복적으로 드러나는 자기 설명의 핵심어는 `lyrical`(서정적), `jagged`(거칠고 각진), `restraint`(절제), `atmosphere`(분위기), `tone`(정조·톤), `ambiguity`(모호성), `repetition`(반복), `precision`(정밀성), `concision`(간결성)이다. 특정 사례에서 `iceberg`와 `calve` 같은 구체어를 선택해 이미지를 명료화하기도 한다. 이는 고정 번역어 목록이 아니라 판단을 설명하는 메타 어휘다.

한국어 윤문에 적용할 때는 다음처럼 바꿔 읽는다.

| Smith식 판단 언어 | v7에서의 한국어 검토 질문 |
|---|---|
| lyrical / jagged | 문장이 매끈해지면서 원문의 결·긴장이 사라지지 않았는가 |
| restraint | 설명·감정·강도 부사를 덧대지 않았는가 |
| atmosphere / tone | 장면의 정조와 화자의 거리가 유지되는가 |
| ambiguity / repetition | 의미 있는 모호성과 반복을 성급히 해설·동의어화하지 않았는가 |
| precision / concision | 모호성을 임의로 확정하지 않으면서 불필요한 말만 줄였는가 |

### 반드시 걸어야 할 가드

『채식주의자』 번역에 관해서는 주어 복원, 단어 추가·삭제, 감정 강도와 초점화의 변화가 비평의 쟁점이 됐다. 그러므로 Smith의 독자 지향적 재구성은 참고하되 다음은 허용하지 않는다.

1. 한국어의 생략 주어를 근거 없이 `그/그녀`로 명시한다.
2. 원문에 없는 감정·평가·강도 부사를 추가한다.
3. 반복·모호성·꿈·회상·인물 단서를 읽기 좋다는 이유로 삭제한다.
4. 영국식 또는 빅토리아풍 영어 어휘를 한국어 문체의 규범으로 이식한다.
5. 해석이 필요한 지점을 사실처럼 단정하고, 그 단정을 윤문으로 위장한다.

문학 번역에서 `creative rewriting`은 무제한 각색의 허가가 아니다. v7의 기본선은 **정조와 가독성은 개선할 수 있지만, 사건·화자·단서·불확실성은 보존한다**이다.
